# 接收缓冲优化（2026-10-29）

- MQTT 原始报文先提交本机 spool/mqtt.sqlite3（SQLite WAL、同步 FULL），4 个线程按 Topic 顺序处理，Redis 成功后删除。失败保留重试，重启续传。
- MQTT 磁盘有效负载上限 4 GiB，OA 超时补写缓冲上限 1 GiB；原 max_bytes=200 MiB 配置保留。磁盘达到上限会拒绝新包并记录缺口，不无限增长。磁盘缓冲不能保障无限故障期间不丢包。
- 无效 MQTT 报文进入 rejected 隔离表，保留原文并计入容量，不堵住后续正常报文。
- OA 直接写成功时返回原响应；Redis 写超时而本地落盘成功时返回 HTTP 202，success=true、buffered=true、cached=0、queued=条数。表示已持久接收，尚未写入 Redis。落盘失败返回 503，可重试。
- OA 最新值合并 MSET，接收信息合并 HSET。最新值不再重复包含 receipt 副本；补写不会倒退最后接收时间。
- 历史仍按发送时间每5秒整点采样，最近180分钟；减少重复 EXPIRE，保持 AOF 开启和 everysec 策略。新增解析及写入分段耗时。
- spool 库应与接收程序一同保留。首次切换旧进程的纯内存队列不能迁入磁盘，切换有采集缺口；不能宣称既有丢包已恢复。
- 30项接收/磁盘队列测试通过（独立6380测试Redis），100项监测平台测试通过。包括Redis超时重试、重启续传、上限拒收、乱序防倒退与OA缓冲响应。
## 整包时间筛选与线程隔离（追加）

- paho 网络回调只向有界内存队列入队（10000包 / 200 MiB），没有 JSON 解析、SQLite 提交或 Redis 写入。
- 独立 spool_writer 线程解析整包 timestamp，只有 floor(timestamp/1000) % 5 == 0 的包才落盘。毫秒尾数保留，点位 t 不用于筛选；其他秒的包按用户要求过滤，不更新最新值、不写历史。
- 4个独立 Redis 写入线程从磁盘按 Topic 顺序取包，成功后确认；旧磁盘积压也执行相同时间筛选。
- filtered_packets 是主动时间筛选计数，dropped_packets 是容量等故障丢包，两者区分。
- 网络内存队列尚未落盘的数据在进程强制退出/断电时仍可能丢失，磁盘队列可重启恢复；不承诺所有收包均已持久化。
- 33项测试通过，新增网络回调不访问磁盘/解析器、按外层发送时间筛选、筛选在落盘之前执行的测试。
## 包头提前过滤与6线程（2026-10-30）

- packet_header.py只提取顶层timestamp，不构造values点位对象；当前网关timestamp在首字段，能在读取报文头后立即筛掉非目标秒的包。
- 若timestamp位于其他字段后面，只做JSON词法跳过，不把点位数组解析成Python对象；不误认点位内的时间字段。
- 筛选在独立线程执行，网络回调继续只入内存队列。通过筛选的包才落盘和完整解析。整秒能被5整除，毫秒尾数不要求为000。
- writer_threads=6，仍按Topic维持处理顺序，因此单Topic不会因加线程自动获得6倍吞吐。
- 新增header_filter_ms、packet_decode_ms、packet_cache_ms、disk_spool_ms、disk_ack_ms，均为最近一次阶段耗时，不是平均值或百分比。
- 37项测试通过；既有磁盘积压保留，不以清空数据方式恢复状态。
## Redis批量读写优化（2026-10-30）

- MQTT快速写入脚本每500点使用HMGET一次读取目录、接收记录、采样时钟，MGET读取最新值，替代逐点HGET/GET。
- 每批历史时钟合并HSET；同批重复EID在本地Lua表中维护最新状态，避免乱序和重复历史。
- 4个500点原子脚本合并一次非事务Pipeline网络往返，保持每个原子脚本规模有界；每次Cache.ingest最多10000点，减少重复统计请求。
- 计数为0的统计字段不再重复递增；HTTP接收结果仍保留完整零值字段。
- 写入部分失败时保留原包重试；独立测试覆盖跨批EID、同EID重复、部分Pipeline失败后重试的历史幂等。
- 40项测试通过。独立6380缓存9860点/包的基准（每组4轮，后三轮均值）：优化前664.42ms，优化后231.77ms，约降低65%。该测试无生产持久化负载，不代表实时服务保证值。
- 同一基准4轮内：HGET118320→0，GET39440→0，HSET39524→164，改用240次HMGET和80次MGET。详细数据见logs/redis-batch-benchmark.json。
- 6个写入线程和现有时间过滤保持；不清空旧磁盘积压，不改动数据库或两个UI版本。
