# 报警操作审计

生效后，通过本平台报警开关发生的操作写入远程 MySQL 的 gpwinccoa.dq_alarm_setting_audit。既有操作没有完整历史日志，不补造记录。直接在其他系统或SQL客户端修改数据库不经过本平台，无法凭本平台日志确认其实际操作者。

记录字段：id（唯一审计号）、requested_at（请求时间，北京时间）、source_committed_at（源库提交时间）、finished_at（操作结束时间）、eid、point、department、process、equipment、group、source、owner_name（点位负责人快照）、actor（实际登录账号，区别于点位负责人）、actor_role、login_at、client_ip（实际连接IP）、user_agent、old_enabled（源库原状态）、local_old_enabled（本平台原状态）、new_enabled（新状态）、action、result、source_saved、target_saved、source_host、target_host、closed_events（关闭的未恢复事件数量）、note、error_type。启用标识1为启用、0为停用；与 autosensor.qualityCheck 的1停用/0启用含义相反，不要混用。未登录的拒绝操作以 anonymous 记录。

result：REQUESTED=请求已记账，尚未确认完成；SOURCE_SAVED=源库已提交；SUCCESS=两库已保存；NO_CHANGE=原本就是请求状态（本次仍记录）；PARTIAL=源库已保存、目标库未确认同步；FAILED=修改未成功；DENIED=权限或请求来源检查拒绝；INVALID=参数错误；NOT_FOUND=点位不存在。中断时可能留下REQUESTED/SOURCE_SAVED，不能把它当成成功。两库不支持跨库原子事务，阶段字段用于区分部分完成。审计插入失败则不执行源库UPDATE，目标库更新与成功审计写在同一个事务中。缓存通知失败时数据库保存结果仍为成功，目录自动重载后生效。

管理员可通过 GET /api/alarm-audit?page=1&eid=xxx&actor=admin&result=SUCCESS 查询（筛选可省略）。未登录不可读取。

查询最近操作：
```sql
SELECT requested_at,finished_at,eid,point,actor,client_ip,
       old_enabled,new_enabled,result,source_saved,target_saved,
       department,process,equipment,`group`,owner_name,note
FROM gpwinccoa.dq_alarm_setting_audit
ORDER BY requested_at DESC;
```

若多人共用admin，记录只能定位到admin账号和客户端IP，不能确定具体自然人；需分配独立账号后才能按人区分。日志不存密码或登录令牌。
