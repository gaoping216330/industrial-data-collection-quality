# MQTT重复发送证据与历史

独立只读监测客户端仍为readMqt_redis_duplicate_monitor，主接收客户端readMqt_redis不受此次部署影响。

新版判定：
1. 同一EID对应不同完整原始点地址，且两地址在10秒内同时活跃，记录“不同MQTT地址共用EID”，保存两条实际地址及各自Topic和采样证据。
2. 同一EID再次出现相同整包发送时间戳，记录同地址重发；内容不同则记录同时间戳内容冲突。原始地址相同就明确显示同地址，不能据此断言存在两个不同配置点。
3. 同一报文内重复出现会记录same_packet证据。
4. 数值相同、发送时间戳更新不算重复；相同地址分布在不同Topic但时间戳不同，不再单凭Topic数量判定重复。
5. 报文只有EID而没有完整地址时标注“报文未提供完整地址”，不使用autosensor.mqttname推测第二个地址。

数据库dq_mqtt_duplicate_event：同一EID/地址及Topic组合的一次持续事件只保存一行，记录id、event_key、两地址、两Topic、开始时间、最近发现、最后重复发送时间、结束时间、恢复确认时间、计数及两次实际观测的JSON证据。
观测在内存持续进行，历史每60秒合并更新；页面仍每600秒汇总最近10分钟的证据，首页按不同EID去重计数，明细按地址对分行。历史页显示全部已持久化事件，支持Excel导出。
连续有正常数据且10分钟不再出现该地址对的重复证据，才确认结束；结束时间取这段连续正常观察的起点，同时另存确认时间。断线、观测漏包、处理落后或观察心跳间隔超过40秒，会重置恢复确认窗口，不把不可观测当作恢复。重启从数据库恢复未结束事件，重新积累连续正常证据。
旧版368条快照当时均来自xgt_float内同时间戳、同内容重复，没有跨Topic记录；旧版未保存完整原始地址，不能从目录反推双地址。部署时保留logs/mqtt_duplicates_legacy_snapshot.json备份，新版从部署后开始取证，不伪造旧事件的双地址或结束时间。

停用检测补充：qualityCheck非0的点位不计入当前数据质量报警、停更统计和报警明细，但采集、趋势和已结束事件历史仍保留。autosensor目录由源库每10分钟同步到本机，判定引擎每10分钟重新扫描本机autosensor，并在收到目录版本变化通知后提前刷新；界面随目录/正式判定版本更新。MQTT重复证据是采集链路诊断，保留原始报文事实，不等同于点位模型报警。
