# 离线记录重置

本次由用户明确要求清理旧的点位离线数据。仅删除dq_quality_event中“从未收到、停止发送”的历史事件，并清除当前点位对应旧离线状态和起点。质量BAD、设备恒值、时间异常、模型异常、报警操作日志、设备人工原因、Redis实时值与趋势样本均保留。

备份位于本目录backups/offline_reset_*.json.gz。首份完整备份保存所有清理前离线事件，后续增量备份通过previous_backup字段关联，保存清理期间新增/变动记录和当时点位状态。大表必须按备份中的id主键分批删除，不使用全表条件DELETE的大事务。

Redis dq:quality:offline_reset_at为重新观察起点。AvailabilityTracker的有效缺失起点使用max(最后真实接收时间,重置起点)，防止几天前的旧接收时间导致刚重置就再次确认离线。真实最后收到时间仍显示实际时间，不伪造新收到数据。新正式停止发送事件的开始时间也不早于重置起点。

设备最早离线取当前已确认缺数据点位的data_missing_since最小值。从未收到只能知道首次发现未收到的时刻，不能追溯实际开始。质量BAD等异常但仍持续收到数据的设备不填离线时间。
