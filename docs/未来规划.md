# 未来规划

依据作者提供的演示文稿整理。以下为发展方向，不代表已经完成的功能，也不承诺交付日期。

## AI辅助运维

利用历史故障和关联点数据，研究轻量模型辅助定位异常原因、过滤无效告警、预判故障和安排维护。当前仓库已有模型推理及结果展示相关代码，但自动根因定位和故障预测仍需独立验证。

## 全链路数据质量监控

统一呈现采集源、接收服务、消息链路、缓存和业务展示的可用性与质量，逐步实现异常自诊断、告警降噪和全链路可视化。现有监测功能是这一方向的基础，不表示全厂全部链路已被覆盖。

## 自研统一采集平台

将采集配置、点位维护和统一数据字典放在同一平台，统一数据模型，逐步降低对特定采集产品的强依赖。需要进一步明确协议支持、驱动授权、写入权限和与KEPServer / WinCC OA共存的实施边界。

## 标准化部署与产品落地

将经过验证的能力沉淀为可复制的部署方案，适配不同钢厂的设备和网络，缩短新厂接入周期。配套工作包括示例配置、安装升级说明、运行诊断、版本管理以及实际验收记录。

## 与历史版本的关系

第一至第四代描述历史采集体系，网页1.0、1.1描述界面版本。未来规划不意味着第五代已经上线。各项能力正式交付时，应以代码、测试结果和发布记录明确完成范围。

历史背景见[项目发展历程](项目发展历程.md)。
