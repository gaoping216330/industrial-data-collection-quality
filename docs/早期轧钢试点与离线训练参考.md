本项目用历史数据自动学习生产工况，并判断目标模拟量与同设备相关信号是否一致。布尔量仅作为工况输入，不作为被诊断对象。

## 当前试点

- 产线：轧钢厂 / 新棒材 / 轧机
- 目标：`00779b68`，新棒材8H传动速度反馈
- 上下文：同机架电流、转矩、其他速度/转速，以及运行、含钢、非零速、停车、允许轧钢等状态量
- 原始数据：`D:\数据中台数据\out.parquet`

`sensor.csv` 中并没有可靠地填写所有测点的数据类型，因此程序会根据历史值中0/1占比自动识别布尔量。配置中的目标始终按模拟量处理。

## 方法

1. 只扫描配置列，按10秒聚合并去除同一时间戳的重复记录。
2. 根据历史0/1占比自动区分布尔上下文和模拟量。
3. 使用布尔状态、负荷模拟量、差分和短期均值进行无监督聚类；在2～7个工况中按轮廓系数自动选择数量。
4. 对过短的工况片段进行持续时间平滑，避免工况每个点来回跳变。
5. 完全排除目标传感器当前值，按工况用其他传感器预测目标正常值。
6. 对训练残差最大的2%进行一次鲁棒剔除后重训，降低历史故障污染。
7. 使用时间顺序65%训练、15%定阈值、20%模拟在线测试，不随机打乱，避免时间泄漏。
8. 分工况计算99.7%残差区间，并用“5点中至少3点异常”确认持续异常。
9. 自动注入偏置、漂移、卡死和噪声故障，形成无标签情况下的基础验证报告。

模型输出的是“传感器与当前工况及相关测点不一致”的证据，不等同于已经证明仪表物理损坏。若所有相关测点同时发生共模错误，纯历史数据模型可能无法识别。

## 输出

默认输出到 `outputs\new_bar_8h_speed`：

- `model.joblib`：训练模型；
- `signal_profile.csv`：测点可用率、自动类型和分布；
- `aligned_timeseries.parquet`：去重、10秒聚合后的模型宽表；
- `historical_judgement.parquet`：完整历史判断；
- `latest_judgement.csv`：最近20,000点，便于人工查看；
- `training_report.json`：工况数、时间切分、误报率和合成故障验证。

判断结果主要字段：

- `actual`：实际值；
- `predicted`：相关信号推断的正常值；
- `prediction_lower/upper`：当前工况正常区间；
- `state`：算法自动发现的工况编号；
- `raw_anomaly`：单点异常；
- `confirmed_anomaly`：持续性确认异常；
- `health_score`：0～100健康分；
- `reason`：异常原因。

## 换目标传感器

编辑 `config.json`：

1. 修改 `target.eid` 和名称；
2. 在 `signals` 中加入目标及同设备、同工艺链的相关模拟量；
3. 加入运行、停机、空转、含钢、联锁等布尔上下文；
4. 保证目标在 `signals` 中只出现一次。

不需要给停机、空转、低负荷、高负荷等历史时段做人工标签。

## 全厂温度、压力、流量模型集

新点表中的 `type` 字段决定训练范围，仅处理“温度”“压力”“流量”。给定值、设定值、目标值和调节阀输出可作为相关上下文，但不会被判定为传感器；累计流量按累计表单独建模。

```powershell
python build_full_scope.py --sensor sensor.csv --output outputs\full_ptf
python extract_full_ptf.py `
  --scope outputs\full_ptf\scope_eids.csv `
  --output outputs\full_ptf\cache_10s
python train_full_ptf.py `
  --scope outputs\full_ptf\training_scope.csv `
  --cache outputs\full_ptf\cache_10s `
  --output outputs\full_ptf\models
```

在线或批量判断的输入是长表，至少包含 `ts,eid,v` 三列。同一批可同时提供多个 EID；程序自动加载这些 EID 所属的模型和相关点位，不是只输入一个 EID 字符串。

```powershell
python score_full_ptf.py `
  --manifest outputs\full_ptf\models_production\manifest.json `
  --input current_data.parquet `
  --output outputs\full_ptf\current_judgement `
  --latest-only `
  --eid 5865e953
```

`--eid` 只限制要输出结论的目标；输入文件仍应包含该目标所属设备组的相关 EID 数据，否则相关数据覆盖率不足时会输出“无法判断”。最省事的生产接法是每次提供目标设备组最近 30 分钟的全部点位；大多数相关模型使用 3～5 分钟即可判断，30 分钟同时覆盖温度慢变量和少量单变量回退模型。单独 1 秒只能给初步结果，不能可靠判断卡死、漂移和持续异常。

输出目录包含 `sensor_health.parquet`、`sensor_health.csv` 和 `summary.json`。默认部署门槛如下：

- `ready`：可输出正常/异常；
- `observation_only`：只输出“观察模式”，先与现场记录对照；
- `needs_recalibration`：输出“模型待校准”，不能直接联动报警；
- `untrainable`：历史缺失、恒值或有效样本不足，没有生成模型。

只有明确传入 `--allow-unvalidated` 时，观察或待校准模型才会输出正常/异常结论。生产环境不建议默认开启该选项。

### BOOL工况增强

程序从点表的2,348个BOOL点中先按设备组和语义筛选运行、启动、停止、允许轧钢、有钢、自动/手动等状态，再根据20天历史的0/1切换次数剔除恒定点。最终46个BOOL具备有效历史变化，其中验证确有改善的21个用于“新棒材/轧机”和“棒材/旋流”生产模型。

- `models`：不含BOOL的基础模型；
- `models_with_bool`：所有可用BOOL都参与的对比模型；
- `models_production`：按设备组验证后选出的生产混合模型，正式调用应使用该目录的 `manifest.json`。

BOOL只用于识别停机、空转、轧制和不同负荷工况，不会输出BOOL传感器异常。调用上述两个BOOL增强设备组时，输入长表应同时包含相应BOOL EID；其他设备组仍只需要原模拟量上下文。
